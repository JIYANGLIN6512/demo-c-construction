## 四、修复记录（本轮自己发现并修掉的）

| 问题 | 修法 | 修前 → 修后 |
|---|---|---|
| `.card__tag`、`.step__no` 用强调色小字，对比度不足 | 强调色由 `#d97b16` 加深为 `#a85405`（白底 5.34:1、页面底 4.98:1） | 无障碍 94–95 → 100 |
| 案例页标题层级跳跃（h1 后直接 h3） | 案例网格前加 `<h2 class="sr-only">案例列表</h2>` | `heading-order` 报错 → 通过 |
| 业务服务页标题层级跳跃 | 服务网格前加 `<h2 class="sr-only">业务范围</h2>` | 同上 |
| 资质证书用 `figure[role=button]`，`role` 不允许 | 改为真正的 `<button type="button">`，标题移入 `.cert__caption` | `aria-allowed-role`、`label-content-name-mismatch` → 通过 |
| 资质清单表在 375px 靠横向滚动兜底 | 窄屏表格转堆叠列表（`td::before` 用 `data-label` 显示列名） | 越界元素 18 → 0 |
| 首屏图过重 | hero 由 1800px/155KB 降到 1200px/57KB；其余图按显示尺寸重出（合计 1449KB → 739KB） | LCP 3.5 s → 2.1 s |
| 缺 favicon，控制台 404 | 自绘 `assets/img/favicon.svg` 并在五页 `<head>` 引用 | 最佳实践 96 → 100 |
| 电话标注首版用了 `opacity: 0.85`，12px 文字对比度跌破 4.5:1 | `.demo-note` 去掉 opacity，只保留 12px 与左边距，颜色继承父级 | 无障碍 100 → 95–96 → **100**（修回后与改动前持平） |
| 首屏大图走外链时在境内常等十几秒（AC-D13） | 首屏 hero.webp 以 base64 **内联**进 `index.html`（76.2 KB → HTML 89.1 KB），并删掉 hero 的 `preload`；其余 10 张图保持外链 | 本地 index 性能 99 → **100**、LCP 2.1 s → **1.7 s**（未出现预期中的掉分）；代价：首屏图不可被浏览器缓存复用，每次访问重传 76 KB |

## 五、线上访问实测

- 链接：<https://jiyanglin6512.github.io/demo-c-construction/>（GitHub Pages，源仓库 `JIYANGLIN6512/demo-c-construction`，公开仓库，免 ICP）
- 五页均返回 200：index / services / cases / qualifications / contact 均可打开，页面内容为新版本（已核对含「恒川装饰工程」字样）。
- 资源文件：base.css 2.3 s / site.js 2.5 s / hero.webp 1.9 s / favicon.svg 1.9 s（已缓存）。
- **HTML 页面延迟波动极大**（本机，境内网络）：同一页面多次请求实测 0.9 s / 1.2 s / 4.6 s / 7.9 s / 21.9 s / 24.0 s / 26.5 s / 30.6 s / 41.1 s / 53.7 s，有 1 次 60 s 超时。
- **IPv6 路径不通**：`jiyanglin6512.github.io` 的 IPv6（2606:50c0:8003::153）在本机直接失败（000，0.008 s），curl 默认先试 IPv6 再回落 IPv4，故默认耗时略高于 `-4`（实测 4.6 s vs 7.9 s）。
- 已做的减负：全站图片转 WebP 并压到 739 KB（首屏图 57 KB）、HTML 每页 13 KB、零外部请求、不加载第三方脚本与外部字体文件、首屏图加 `preload`。
- **待协调（唯一一件）**：换境内可达的托管节点 —— Cloudflare Pages（选香港/新加坡）或一台香港轻量服务器。站点为纯静态、零改动即可迁走，迁走后需要的是账号/令牌，不是改代码。
